# Hannto QA 资源与实际点数数据契约

状态：**已冻结（v1）**
适用范围：工作台、工作事项、项目排期、团队资源、质量报表、版本与发布。

本文件是资源算法的唯一业务口径。页面文案、图表颜色和数据库汇总不得自行重新解释这些字段。

## 1. 时间与工作日

- 业务时区统一为 `Asia/Shanghai`。
- 业务日期统一为 `YYYY-MM-DD`；完成时间、创建时间等审计时间使用服务器时间戳。
- 工作日由统一工作日历决定。周末、法定节假日及容量为 0 的日期不能分配标准计划或标准实际点数。
- 上午、下午各占当天容量的 50%；半日用于排期定位，不改变成员当日总容量。
- 当日延期在 **23:59（含）后** 才成立。当天 23:59 前不得显示“已延期”，也不得向次日滚动延期占用。

## 2. 计划点数

- 计划点数来自工作事项负责人分配的 `allocated_effort`，单位为人天点。
- 同一成员同一天的标准计划容量默认是 `daily_capacity`，通常为 `1.00`。
- 多个事项按排期起止时间和工作日历占用容量；已完成事项仍保留历史计划占用，不能因完成而从历史资源表消失。
- 未来排期：小于容量为“可用”，等于容量为“排满”，大于容量为“超负荷”。这套颜色只描述计划，不描述实际表现。

## 3. 实际点数

- 实际点数是系统证据，不是负责人主观填写的“我今天用了多少人天”。
- TestHub 事项按负责人实际执行 Case 占其目标 Case 的比例换算；手工事项按累计完成百分比/进度增量换算。
- 手工事项最终填报形成的累计实际点数，按该事项**最早可用工作日开始依次向后填充**；单日标准实际不得超过成员当日容量。
- 示例：累计完成 `2.90` 点，应分配为 `1.00 + 1.00 + 0.90`，不得把 `2.90` 全记在最后填报日。
- 已有其他事项占用 `0.70` 实际点时，新事项当天最多填入 `0.30`，剩余点数继续填入后续工作日。
- 当天完成的事项点数仍计入当天历史实际，状态变为“已完成”不删除资源记录。
- 超过每日容量的部分单独记为 `overflow/overtime`，不得混入标准实际点。加班点必须来自审批或可信时间证据。

## 4. 延期滚动

- 延期剩余量 = 负责人分配总点数 - 截止时累计实际点数。
- 仅当事项未完成、未被管理员豁免，并且已过截止日 23:59，剩余量才开始滚动。
- 延期剩余量按后续工作日逐日占用容量；第一天未完成，第二天、第三天继续显示，直到完成或管理员解除延期。
- 完成晚于原截止时间时保留“延期完成”历史标记。只有管理员调整原排期或显式解除延期，标记才可清除。
- 延期占用与当天实际分开显示，避免把“尚未完成的剩余工作”误认为“当天已经完成的工作”。

## 5. 展示和筛选

- 资源页必须提供“计划 / 实际 / 综合”三个视角。
- 计划颜色不得复用为实际评价：计划看容量是否排满；实际看标准容量、超额与证据。
- BU、项目、版本、成员均使用稳定 ID 关联。名称只用于展示，不作为唯一关联键。
- BU 过滤必须同时约束成员、工作事项、项目、版本和发布数据，不能只切换页面标签。

### 5.1 项目月度人力三口径

- **需求人力**：项目负责人按月维护的预算基线，用于回答“业务希望投入多少人”。不得由事项自动反推覆盖。
- **已排人力**：关联工作事项在该月的负责人分配点数 ÷ 该月工作日，用于回答“已经具体排下去多少人”。跨月事项只按落在本月的有效工作时段分摊。
- **实际投入**：关联事项在该月形成的系统证据点数 ÷ 该月工作日，用于回答“实际发生了多少投入”。不得把历史累计值重复显示到未来月份。
- 三项必须并列展示，不允许用单一“项目人力”字段同时承担预算、排期和实际三个含义。
- 差异解释：`需求 - 已排` 表示尚未拆解的预算；`已排 - 实际` 表示执行进度差；实际大于已排时单独标为超计划投入，不反向篡改需求基线。

## 6. 数据来源

| 含义 | 首选来源 |
|---|---|
| 负责人及分配点数 | `qa_task_assignees` |
| 排期与状态 | `qa_tasks` |
| 手工进度证据 | `task_progress_logs` |
| TestHub 日执行证据 | `task_testhub_daily_execution` |
| 工作日/节假日 | 统一工作日历表及页面缓存 |
| 日容量 | `profiles.daily_capacity` 与容量例外 |
| 延期豁免 | `qa_tasks.delay_waived_at` 及审计记录 |

## 7. 必须长期成立的不变量

1. 任一成员单日标准实际点 `<= daily_capacity`。
2. 标准实际点 + 超额点 = 原始实际证据点。
3. 已完成事项的历史计划和实际不会消失。
4. 23:59 前不产生当天延期滚动。
5. 非工作日不承接标准计划、标准实际或延期滚动。
6. 多负责人数据按成员独立计算，不能平均覆盖真实 TestHub 执行人。
7. 页面、报表和导出对同一事项/成员/日期给出相同结果。

## 8. 变更规则

修改本口径必须同时：

1. 更新本文件；
2. 更新 `src/shared/resource-accounting.js`；
3. 增加或修改 `tests/resource-accounting.test.js`；
4. 通过 `python scripts/quality_gate.py`；
5. 在 PR 中说明历史数据是否需要迁移或重算。
