# Liene QA「我的今日工作台」MVP 规格

## 1. 目标

让 QA 登录后 30 秒内回答三个问题：

1. 我今天优先做什么？
2. 当前有哪些需要马上处理的风险？
3. 常用工作能否在两次点击内开始？

本阶段只定义产品与数据规格，不创建数据库表，不修改线上页面。

## 2. MVP 范围

### 本期包含

- 当前日期、用户与当前版本概览。
- 四个关键指标：今日待办、自动化失败、离线设备、低库存耗材。
- 「我的今日任务」列表。
- 「风险提醒」列表。
- 五个快捷操作。
- 加载、空数据、无权限和请求失败状态。
- 电脑端和窄屏基础适配。

### 本期不包含

- PingCode 写回。
- 自动创建 BUG。
- 完整质量报表。
- Allure 报告嵌入。
- 钉钉通知。
- AI 自动判断发布结论。
- APP、固件安装包管理。

## 4. 指标与数据来源

| 指标 | 第一版定义 | 数据来源 | 当前是否具备 |
|---|---|---|---|
| 今日待办 | 当前用户未完成且截止日期不晚于今天的任务 | `qa_tasks` | 需要新增 |
| 自动化失败 | 最近 24 小时 `status = failed` 的任务数 | `run_tasks` | 已具备 |
| 离线设备 | 标记为不可用或心跳超时的自动化设备数 | `device_configs` | 部分具备，需确认心跳字段 |
| 低库存耗材 | `quantity <= threshold` 的耗材数 | `consumables` | 已具备 |

当某项数据表或字段尚未建立时，页面显示「待配置」，不能用 `0` 冒充真实结果。

## 5. 今日任务字段

建议任务最小字段如下，最终 SQL 在下一阶段确定：

| 字段 | 用途 |
|---|---|
| `id` | 任务唯一标识 |
| `title` | 任务标题 |
| `task_type` | PRD评审、用例、执行、BUG验证、文案、其他 |
| `priority` | P0、P1、P2 |
| `status` | 待处理、进行中、已完成、已取消 |
| `assignee_id` | 负责人，对应 Supabase 用户 |
| `due_date` | 截止日期 |
| `related_type` | PRD、自动化任务、BUG、文案等关联类型 |
| `related_id` | 关联对象 ID |
| `created_by` | 创建人 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |

任务排序规则：

1. 已逾期任务优先。
2. P0 在 P1、P2 前。
3. 同优先级按截止时间升序。
4. 已完成和已取消任务不出现在今日列表。

## 6. 风险规则

第一版使用明确规则，不使用不可解释的 AI 评分。

| 编号 | 风险 | 等级 | 数据来源 | 触发条件 |
|---|---|---|---|---|
| R01 | 自动化执行失败 | 高 | `run_tasks` | 最近 24 小时存在失败任务 |
| R02 | 自动化运行超时 | 高 | `run_tasks` | `running` 持续超过 2 小时 |
| R03 | 自动化设备离线 | 高 | `device_configs` | 设备离线或心跳超过阈值 |
| R04 | P0任务逾期 | 高 | `qa_tasks` | P0 未完成且超过截止时间 |
| R05 | 普通任务逾期 | 中 | `qa_tasks` | P1/P2 未完成且超过截止时间 |
| R06 | 耗材库存不足 | 中 | `consumables` | `quantity <= threshold` |
| R07 | 当前版本未设置 | 低 | `releases` | 没有活动版本 |

PingCode P0/P1 BUG、多语言缺失和测试覆盖率风险放到后续版本，因为当前仓库没有稳定的数据源。

## 7. 快捷操作

| 操作 | MVP 行为 |
|---|---|
| 运行冒烟 | 打开自动化测试页面并预选冒烟测试 |
| 新建待办 | 打开轻量弹窗，填写标题、优先级、负责人和截止日期 |
| 打开 PRD | 进入 PRD 管理页面 |
| AI 写用例 | 打开现有 QA Pipeline |
| 生成摘要 | 在浏览器生成今日任务与风险文本，允许复制；暂不自动发送 |

## 8. 页面状态

### 加载中

- 指标卡显示骨架或 `…`。
- 禁止短暂显示错误的 `0`。

### 空数据

- 没有任务：显示「今天没有待办，可以检查版本风险」。
- 没有风险：显示「当前没有发现阻断风险」。

### 请求失败

- 单个卡片独立显示「加载失败」和重试入口。
- 一个接口失败不能阻止其他卡片显示。
- 记录具体模块和操作，禁止静默 `catch {}`。

### 无权限

- 普通成员只查看自己的任务。
- 团队风险对所有已登录成员可见，只有管理员可以修改版本和发布检查规则。
- 页面隐藏按钮只负责体验，数据库 RLS 才负责真正授权。

## 9. 交互规则

- 点击指标卡进入对应的筛选结果，而不是只显示数字。
- 点击任务可进入关联 PRD、自动化任务或其他对象。
- 完成任务后只更新对应任务和指标，不整页刷新。
- 当前活动版本由全团队统一设置；用户可以筛选历史版本，没有活动版本时显示「暂未设置」。
- Realtime 只监听任务和自动化状态变化，且每个频道只订阅一次。

## 10. 验收标准

- 用户登录后 30 秒内能识别最高优先级任务和风险。
- 指标均来自真实数据，缺少数据源时显示「待配置」。
- 五个快捷操作最多两次点击可到达目标。
- P0、逾期、失败、离线和低库存规则结果正确。
- 普通成员无法修改他人任务或版本规则。
- 单个数据请求失败不影响其他区域。
- 窄屏下指标卡和双栏内容自动变为单栏。
- 不新增硬编码服务端密钥。
- JavaScript 语法与 `git diff --check` 通过。

## 11. 下一阶段需要确认的数据

第三步只做数据盘点和 SQL 草案，需要确认：

1. `device_configs` 是否已有 `last_seen_at` 或等价心跳字段。
2. 是否已有版本表；若没有，新增 `releases`。
3. 是否已有个人待办表；若没有，新增 `qa_tasks`。
4. PingCode 写接口的正式端点、字段 ID 和测试环境。
